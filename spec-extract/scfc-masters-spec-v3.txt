1 · Why these changes
The current v2 curriculum maps approximately to MS&E 260 (Introduction to Operations
Management) and the operations portion of OIT 262 — solid undergrad / first-year-MBA
territory. To reach the breadth and depth of a Stanford MS in supply chain (i.e., MS&E
coursework plus elective OIT coursework), the curriculum needs:

More domains. Stanford MS&E and GSB OIT collectively cover six areas v2 doesn’t touch
with discipline:

    Operations Research / Network Optimization — the spine of MS&E 211, 212, 260, OIT
    245/247/248. Linear programming intuition, facility location MILP, vehicle routing. v2
    mentions LP in one lecture day; the canon deserves a domain.

    Sustainability & Climate Operations — Erica Plambeck’s home territory at Stanford.
    Scope 3 carbon, supplier emissions, operational hedging against climate risk, the
    Walmart sustainability index. v2 has one lecture day on Scope 3; the field has a decade
    of canonical work behind it.

    Geopolitics & Industrial Policy — CHIPS Act, IRA, friend-shoring, decoupling. None of
    this existed in v1 textbooks. It’s what supply chain operators actually face in 2026.

    Healthcare & Pharma Supply Chain — MS&E 263 (Healthcare Operations) is a full
    Stanford course. Cold chain, DSCSA serialization, FDA compliance, vaccine distribution.
    None in v2.

    Semiconductor Supply Chain — TSMC concentration risk, allocation under shortage,
    lead times of 26+ weeks, the lithography monopoly. The most-discussed supply chain
    on earth right now, and v2 doesn’t mention it.

    Behavioral Operations — Sterman’s beer game, Croson on bullwhip behavior, Gino-
    Pisano on heuristics, Bendoly’s bodies of knowledge. Stanford OIT and MIT Sloan both
    teach this; v2 mentions bullwhip’s behavioral roots but doesn’t develop the field.

More math. v2 has three quantitative panels (EOQ, newsvendor, EVPI). A real Stanford MS
student derives these results, doesn’t just compute them. v3 adds a derivation panel for ~8
capstone days where the math is the lesson, not the answer. These days are 15–20 minutes
(vs the 5-minute default), explicitly marked, and optional in the sense that progressing past
them requires only completing them, not deriving from memory.

More breadth in the canon. v2 cites 22 works. v3 adds 18 more, weighted toward Stanford
faculty and OIT-area canonical research: Hau Lee on Triple-A, Plambeck on sustainability,
Bimpikis on COVID supply, Sterman on systems dynamics, Pisano on capabilities,
Brandenburger-Stuart on value capture.

Honest about what 8–12 weeks delivers. A Stanford MS is two years of full-time study.
SCFC delivers, at the new bar, a working principal’s fluency across that body of knowledge
— not the proofs, the published papers, or the research career. The product positions as
“Foundation 60” (the existing v2 60 days, slightly reorganized) plus “Mastery +20” (an
optional extension covering the new domains and capstones). A user who completes both
has 80 days of structured engagement against the canon.

2.2 Two-tier program structure
The 80 days are presented as two tiers. The toggle UI is a small badge on the nameplate
( §7.4 ).

    Foundation 60 (Days 1–60): the v2 curriculum, slightly reorganized so days 56–60
    (which were “Applied” in v2) become the lead-ins to the Mastery extension. The existing
    reference build is the Foundation tier verbatim.

    Mastery +20 (Days 61–80): the new content. Six new domains × ~3 days each, plus 1–2
    capstone days per new domain. A user must complete Foundation before Mastery is
    unlockable (mode toggle is locked until day 60 is complete).

The user can replay Foundation days from the curriculum grid at any time. Mastery days
appear in the grid only after Foundation completion.

Day 62 — Newsvendor Derivation (capstone, lecture+derivation)
  dom: 3 (INVENTORY — extends v2)

  f: Newsvendor · First-Order Optimality

  o: Edgeworth (1888); Arrow, Harris & Marschak (1951)

  cite: Arrow, K. J., Harris, T. & Marschak, J. “Optimal Inventory Policy.” Econometrica
  19(3), 1951.

  sum: The critical fractile result Q* such that F(Q*) = Cu/(Cu+Co) is not magic. It falls out
  of differentiating the expected cost function and setting it to zero. Doing the derivation
  once changes how you think about every stocking problem.

  dur: 18

  cap: true

  deriv: full derivation (see schema §6.3 below for format)

  The v2 day 12 case (newsvendor promo buy) remains. This new day 62 is its companion
  derivation, optional but recommended.

  content (lecture-style, with derivation panel):

     brief: We’ve used the newsvendor formula. Now we prove it. This is one of the
      cleanest applications of first-order optimality conditions in operations research. If
      you can derive it, you can derive its variants — multi-item, capacity-constrained,
      price-dependent — without help.

      derivation steps (rendered as the new derivation panel):

       1. Setup: Demand D is a continuous random variable with CDF F(d) and density
          f(d). Order quantity Q is the decision. Per-unit underage cost is Cu (margin lost
          when D > Q). Per-unit overage cost is Co (scrap cost when D < Q).

       2. Expected cost: For a given Q,

            E[C(Q)] = Co · ∫₀^Q (Q − d) f(d) dd          +   Cu · ∫_Q^∞ (d − Q) f(d) dd


       3. Differentiate w.r.t. Q (Leibniz rule):


            dE[C]/dQ = Co · F(Q)     −    Cu · (1 − F(Q))
                      = (Co + Cu) · F(Q)      −     Cu


       4. First-order condition: Set dE[C]/dQ = 0:

            (Co + Cu) · F(Q*) = Cu
            F(Q*) = Cu / (Co + Cu)                 ← the critical fractile


       5. Second-order check: d²E[C]/dQ² = (Co + Cu) · f(Q) ≥ 0, so Q* is a minimum.

       6. Interpretation: F(Q*) is the probability of not stocking out at Q*. It equals the
          ratio of the cost of one too few to the cost of one too few plus one too many.
          When Cu >> Co, F(Q*) → 1 (stock high). When Co >> Cu, F(Q*) → 0 (stock low).

      principal framing (replaces fr): THE DERIVATION IS WORTH MORE THAN THE
      FORMULA. ONCE YOU’VE DIFFERENTIATED THE NEWSVENDOR EXPECTED-COST
      FUNCTION, EVERY VARIANT — DEMAND CORRELATED ACROSS PRODUCTS,
      PRICE-DEPENDENT DEMAND, BACKLOGGABLE SHORTAGE, MULTI-PERIOD
      INVENTORY — IS A FAMILIAR EXTENSION RATHER THAN A NEW MYSTERY. THIS IS
      THE DIFFERENCE BETWEEN A USER OF OPERATIONS RESEARCH AND A
      PRACTITIONER OF IT. ARROW, HARRIS & MARSCHAK (1951) FORMALIZED THE
      PROOF; THE PRINCIPAL DOES IT ONCE EVERY FEW YEARS TO STAY HONEST.


Day 63 — Network Optimization Intuition (case)
   dom: 13 (NETWORKS — new)

   f: p-Median Facility Location · MILP
o: Hakimi (1964); ReVelle & Swain (1970); Daskin (2013)

cite: Daskin, M. S. Network and Discrete Location: Models, Algorithms, and
Applications. 2nd ed., Wiley, 2013.

sum: The p-median problem chooses p facility locations from a set of candidates to
minimize total demand-weighted distance to customers. It’s the foundational supply
chain network design model and a binding constraint on every DC discussion.

Day 64 — Vehicle Routing Problem (lecture)
   dom: 13 (NETWORKS)

   f: VRP · NP-Hard Combinatorial Optimization

   o: Dantzig & Ramser (1959); Toth & Vigo (2014)

   cite: Toth, P. & Vigo, D. Vehicle Routing: Problems, Methods, and Applications. SIAM,
   2014.

   sum: The Vehicle Routing Problem assigns a fleet of vehicles to customer locations such
   that total distance/time is minimized subject to capacity, time-window, and driver-shift
   constraints. NP-hard in general — practitioners use heuristics (savings algorithm, tabu
   search, large neighborhood search). Solving VRP well at scale is worth single-digit
   millions per year for any large logistics network.

   dur: 5


Day 65 — Queueing Intuition · Little’s Law (lecture)
   dom: 10 (ANALYTICS)

   f: Little’s Law · L = λ × W

   o: Little (1961); Erlang (1909) for the discipline

   cite: Little, J. D. C. “A Proof for the Queuing Formula: L = λW.” Operations Research 9(3),
   1961.

   sum: For any stable system, average number in system = arrival rate × average time in
   system. Holds for manufacturing WIP, customer service queues, hospital throughput,
   even API request handling. The most-used result in operations research.

   dur: 5


Day 66 — Queueing Capstone (capstone)
   dom: 10 (ANALYTICS)

   f: M/M/1, M/M/c, Erlang C

   o: Erlang (1909); Allen-Cunneen for approximations

   cite: Hopp, W. J. & Spearman, M. L. Factory Physics. 3rd ed., 2008. (Ch. 8)
sum: How many docks does a DC need? How many service desks at peak? Erlang’s
queueing models give defensible answers. The math is non-trivial but the intuition is
clean: utilization × variability = wait. As ρ approaches 1, wait blows up.

dur: 18

cap: true

deriv: full

content (lecture+derivation):

    brief: A DC has a single inbound dock receiving trucks. Arrivals are roughly Poisson,
    service is roughly exponential. How does wait time scale with utilization?

    derivation steps:

    1. Setup: M/M/1 queue. Arrivals λ (per hour), service rate µ (per hour). Utilization ρ
          = λ/µ. Stable if ρ < 1.

    2. State probabilities (steady-state, derive from balance equations):

            π_n = ρ^n · (1 − ρ),       for n = 0, 1, 2, ...


    3. Average number in system:


            L = Σ n · π_n = ρ / (1 − ρ)


          Derivation uses Ʃ n·ρ^n = ρ/(1−ρ)² for |ρ| < 1.

    4. Apply Little’s Law (L = λW):

            W = L / λ = 1 / (µ(1 − ρ))


    5. Wait time in queue alone (excluding service):

            Wq = ρ / (µ(1 − ρ)) = (1/µ) · ρ/(1−ρ)


    6. The pole at ρ = 1: wait time goes to infinity as utilization approaches 1. This is
          the fundamental tradeoff of operations: you cannot run at 100% utilization and
          have low wait. Variability requires slack.

    7. Numerical example: ρ = 0.7 → average wait ≈ 2.33 service times. ρ = 0.9 → 9.0.
          ρ = 0.95 → 19.0. The cost of pushing utilization is non-linear.
      fr: ERLANG (1909) AND LITTLE (1961) GAVE OPERATIONS THE QUEUEING CANON.
      THE PRACTICAL INSIGHT THAT EVERY MANAGER MUST INTERNALIZE: WAIT TIME
      IS NOT LINEAR IN UTILIZATION — IT IS HYPERBOLIC. RUNNING A DC AT 95%
      UTILIZATION DOES NOT COST 5% MORE WAIT THAN 90% — IT COSTS 2× MORE.
      ANY SCHEDULER WHO PUSHES UTILIZATION TO THE CEILING WITHOUT
      QUANTIFYING THE QUEUEING COST IS DOING ARITHMETIC AGAINST PHYSICS.
      THE PRINCIPAL TARGETS UTILIZATION IN THE 70–85% BAND FOR VARIABLE
      SYSTEMS, ACCEPTS HIGHER ONLY WHERE VARIABILITY IS LOW.

Day 69 — Sustainability Capstone · Carbon Math (capstone)
  dom: 14 (SUSTAIN)

  f: Activity-Based Scope 3 Calculation

  o: WRI/WBCSD GHG Protocol Scope 3 Standard (2011)

  cite: GHG Protocol. Corporate Value Chain (Scope 3) Accounting and Reporting
  Standard. WRI/WBCSD, 2011.

  sum: Calculating Scope 3 from real procurement data — not estimates, not industry
  averages. The Standard defines five calculation methods; the principal picks the right
  one based on data quality and audit defensibility.

  dur: 18

  cap: true

  deriv: full

  content:

      brief: You receive 480,000 cases of shell eggs annually from a single supplier. EPA
emission factors and supplier-specific energy data are both available. How do you
compute the Scope 3 Category 1 (“Purchased Goods”) emissions?

derivation steps:

1. Method hierarchy (per GHG Protocol Scope 3 §7.3.4):

       Method 1: Supplier-specific (highest quality)

       Method 2: Hybrid (supplier-specific + average)

       Method 3: Average-data (industry emission factor × physical units)

       Method 4: Spend-based (industry factor × $ spent)

2. Method 3 calculation (most common in practice):

     Emissions (tCO₂e) = Activity × Emission Factor
                         = 480,000 cases × 30 dozen/case × 12 eggs/dozen
                             × 4.8 g CO₂e/egg (USDA EPA factor for shell eggs)
                         = 480,000 × 360 × 4.8 g
                         = 829,440,000 g
                         = 829 tCO₂e/yr


3. Method 1 calculation (supplier-specific, from supplier’s actual energy/feed
   data):

     Supplier reports: 712 tCO₂e/yr for your portion of their volume
     (lower because their layer barns are 14% more efficient than industry avg)

   variable, it is the dominant source of uncertainty. Reducing lead time variance is
   typically cheaper than reducing demand variance, and matters more.

 function migrateFromV2() {
     const v2raw = localStorage.getItem('scfc-masters-v2');
     if (!v2raw) return null;
     try {
         const v2 = JSON.parse(v2raw);
         return {
              version: 3,
              streak: v2.streak || 0,
              currentDay: v2.currentDay || 1,
              lastCompletedDate: v2.lastCompletedDate || null,
              completions: v2.completions || [],
              domains: {
                   ...v2.domains,
                   // Initialize new domains (13–18) at strength 0
                   13: { strength: 0 },
                   14: { strength: 0 },
                   15: { strength: 0 },
                   16: { strength: 0 },
                   17: { strength: 0 },
                   18: { strength: 0 }
              },
              tier: (v2.currentDay || 1) > 60 ? 'mastery' : 'foundation'
         };
     } catch (e) { return null; }
 }


 function loadState() {
     // v3 first
     const v3raw = localStorage.getItem('scfc-masters-v3');
     if (v3raw) {
         try { return Object.assign(defaultState(), JSON.parse(v3raw)); }
         catch (e) { /* fall through */ }
     }
     // try v2 migration
     const migrated = migrateFromV2();
     if (migrated) {
         localStorage.setItem('scfc-masters-v3', JSON.stringify(migrated));
         // optionally remove v2 key after successful migration:
         // localStorage.removeItem('scfc-masters-v2');
         return migrated;
     }
     return defaultState();
 }
 function defaultState() {
     return {
          version: 3,
          streak: 0,

          lastCompletedDate: null,
          completions: [],
          domains: Object.fromEntries(DOMAINS.map(d => [d.n, { strength: 0 }])),
          tier: 'foundation'
     };
 }


The v2 key is not deleted after migration unless the user opts in via a palette command.

10 · Out of scope (still — for v3)

   gap detection, no personalized ordering.

   Multi-language. English only.

    generate shareable artifacts.




11 · Definition of done — v3
The v3 build is complete when:

1. All v2 acceptance criteria still pass.

2. Every item in §9 above passes.

3. A user with existing v2 progress can launch v3 and find their state intact.

4. A new user can complete days 1–80 in sequence without encountering a broken state.

5. The reference Stanford alignment is defensible: every new domain has a citation linking
    it to either an MS&E or OIT course or a faculty body of work, and the canonical literature
    for each domain is referenced verbatim.

6. A senior procurement leader (Kyle profile) can finish all 80 days in 8–12 weeks with daily
    5-minute sessions and 8 longer (15–20 min) capstone sessions, and emerge with
    defensible fluency in the supply chain canon at Stanford MS level.

That is the bar. Build to it.

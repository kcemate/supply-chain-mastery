1 · Product overview
1.1 What it is
SCFC (Supply Chain Fluency Coach) is a single-user, single-page, locally-persistent web
app that delivers a 60-day supply chain masters program through daily ~5-minute training
sessions.

The aesthetic is the Machine — a Teenage-Engineering / Dieter-Rams-styled instrument
panel with a green phosphor LCD, mechanical channel buttons, VU meters, and a single
primary action button. Every screen renders inside this panel. There is no “navigation” in the
conventional web sense; views switch by pressing mode buttons on the panel.


1.2 Why it exists
The user is a senior product/sourcing leader pursuing principal-level fluency in supply chain.
Existing learning products are either:

   Aggregator content (LinkedIn Learning, Coursera) — broad, shallow, no decision
   practice.

   Academic textbooks — comprehensive but not actionable in 5-minute increments.

   AI chat tutors — non-deterministic, no curriculum, no progression.

SCFC fills the gap: a deterministic curriculum that names the framework, attributes the
originator, cites the canonical paper, and forces a decision daily. After 8–12 weeks of
disciplined daily use, a working principal should be conversant in the supply chain canon at
a Stanford MS level.


1.3 Hard constraints
   No backend. Everything runs client-side. Data lives in localStorage .

   No login. No accounts. No auth.

   No telemetry. No analytics. No third-party calls except Google Fonts (CSS-level only).

   Works offline after first load (Google Fonts will degrade gracefully — system fonts must
   look acceptable).

   One file is acceptable. A split into index.html / app.css / app.js / data.js is also
   acceptable. Either way, it deploys as static files. No build step.

   Mobile-responsive — the panel must be readable and usable on a 375px-wide phone
   screen. The user is often mobile.


1.4 Non-goals
   Multi-user. There is one user per browser. That’s it.

   Cloud sync.

   Social features.

   Adaptive AI tutoring.

   Generating content at runtime. All scenarios are authored.




2 · Information architecture

2.1 Views
The app has five top-level views, switched by buttons on the mode row:


 Code            Mode button label       Key     Purpose

  home           Today                   H       The current day’s lecture or case

  curr           Curr                    C       The 60-day grid · jump to any day

  glos           Gloss                   G       The glossary of ~50 canonical terms

  read           Read                    R       The reading list (CANON / CORE tiered)

  palette        Cmd                     ⌘K      Command palette overlay


Within home , sub-states drive the scenario flow: briefing → decision → outcome →
debrief .


2.2 No routing
There is no URL routing. Views are switched via JavaScript only. Reloading the page
returns to home with current persisted state. Deep linking is out of scope.


2.3 The “Today” model
state.currentDay is a 1–60 integer. It does not auto-advance based on calendar date. It
advances when:

   The user completes today’s case (any verdict).

   The user marks a lecture day complete.
This means a user who skips three days returns to find the same currentDay waiting. This
is intentional. The product respects the user’s actual progression, not their calendar.

The streak logic is separate from currentDay and is calendar-based (see §11.3).


2.4 Day types
Each curriculum day is one of two types:

   Lecture — framework + originator + citation + summary, no decision. The user reads,
   optionally pulls up the relevant reading list entry, then taps “Mark Lecture Complete.”
   Gives ½ point of domain strength.

   Case — full scenario with brief, optional quantitative panel, 1–2 decisions with 2–3
   options each, outcome, debrief, principal framing. Gives 0–1 point of domain strength
   based on accuracy.

12 of 60 days are cases (specified in §6). 48 are lectures.

3.2 Branching within scenarios
Each decision option may declare .n: <int> (a 0-indexed pointer to the next decision).
Options without .n end the scenario and route to debrief. This allows scenarios to have
early-exit branches. (Example: in the chicken case, accepting the increase ends the
scenario; locking the forward goes to a second decision about communication.)

Decisions are an array. The default progression is sequential ( n=current+1 ), but options
can fork or terminate.

6.2 Curriculum schema

 type Day = {
      d: number;                 // 1..60, day number
      w: number;                 // 1..12, week number
      dom: number;               // 1..12, domain number
      t: string;                 // SHORT TITLE (uppercase, line-broken with \n if needed)
      f: string;                 // Framework name
      o: string;                 // Originator(s) with year
      cite: string;              // Full citation
      sum: string;               // 1–2 sentence summary
      scn: Scenario | null; // If null, this is a lecture day
 };


 type Scenario = {
      tp: string;                // Title plain (sentence case, with em-dash subtitle)
      pre: string;               // 1–2 sentence preface read aloud before brief
      sl: Array<[string, string?]>; // Setup lines: [text, optionalCssClass]
      ctx: Array<[string, string]>; // Context table rows: [label, value]
      qt?: {                     // Optional quantitative panel
           f: string;            // Formula in plain text
           v: Array<[string, string, string]>; // [variable, description, value]
           r: string;            // Result line
      };
      dec: Array<{               // 1–2 decision steps
           p: string;            // Prompt e.g. 'DECISION 01 / 02'
           q: string;            // Question e.g. 'FIRST MOVE.'
           o: Array<{            // 2–3 options
             l: string;          // Label (uppercase)
             v: 'good'|'warn'|'bad';
            s: number;          // -2..+2 score
            c: string;          // Consequence narration (lowercase)
            n?: number;         // If present, next decision index; else terminate
        }>;
      }>;
      opt: number[];            // Optimal pick index per decision (for accuracy %)
      fr: string;               // PRINCIPAL FRAMING (uppercase, multi-sentence)
 };



6.3 The full curriculum

  Verbatim. Do not edit. The framings are written deliberately.

  Author guidance for the agent:

        Lecture days have scn: null . They render the framework card and a “Mark Lecture
        Complete” button.

        Cases must render: title → brief preface → setup lines (typewriter) → context table →
        optional quant panel → CONTINUE → decision → channel commit → outcome → (next
        decision or debrief).

        In all narration c , pre , framing fr : keep the case in the data exactly as given.
        Lowercase consequences, uppercase framings, uppercase setup line text only where
        marked.

WEEK 1 · FOUNDATIONS

Day 1 — TOTAL LANDED COST

   f: TCO Framework

   o: Ellram (1995)

   cite: Ellram, L. M. “Total cost of ownership: an analysis approach for purchasing.”
   IJPDLM, 1995.

   sum: Unit price is rarely the right number. TCO accounts for the full lifecycle: acquisition,
   possession, transformation, disposal.

   Case (full scenario): The Shell-Egg Walkthrough

        tp: Total Landed Cost · The Shell-Egg Walkthrough

        pre: A finance peer asks you to walk them through unit cost on a 30-doz case of
        shell eggs. They have seen “$32.40” and want the stack.
setup lines:

    // initiating: TCO walkthrough [dim]

   blank

    // reference: $32.40 / case (30 doz).

    // stack:

    // feed 60% ($19.44)

    // labor 14% ($4.54)

    // packaging 08% ($2.59)

    // transport 11% ($3.56)

    // distrib. 07% ($2.27)

   blank

    // peer wants the structure. you have 5 min.

context: CASE PRICE=$32.40 · FEED COMP=60% · WINDOW=5 min ·
AUDIENCE=finance peer

decisions:

   D1 “HOW DO YOU WALK IT.”:

       good +2 “BUILD UP / FEED FIRST / TEACH STRUCTURE” → “you taught the
       stack. peer can defend the number with their CFO. compound benefit —
       every future finance conversation about this category starts in the right
       place.”

       warn 0 “TOP-DOWN / CASE → DISTRIB → INPUT” → “they got the answer.
       they did not get the leverage points. they will ask again next month.”

       bad −2 “SEND THE SPREADSHEET” → “you saved 5 minutes. someone else
       will spend 30 next week correcting their misuse of the number in a meeting.”

optimal: [0]

fr: TCO IS A TEACHING FRAMEWORK BEFORE IT IS AN ACCOUNTING ONE. THE
PRINCIPAL TEACHES THE STRUCTURE — INPUT COST, CONVERSION, LOGISTICS,
MARGIN — BECAUSE STRUCTURE COMPOUNDS WHILE NUMBERS DECAY. ELLRAM
(1995) FORMALIZED IT; EVERY QBR SINCE HAS BEEN A SLOPPY IMITATION.
Day 2 — SUPPLY CHAIN MAPPING (lecture)

   f: Tier-N Visibility

   o: Choi & Linton (HBR 2011)

   cite: Choi, T. Y. & Linton, T. “Don’t Let Your Supply Chain Control Your Business.” HBR,
   Dec 2011.

   sum: Most firms know Tier-1. Strategic risk lives at Tier-2 and below. Mapping the
   network is the precondition to managing it.

Day 3 — PUSH vs PULL · DECOUPLING (lecture)

   f: Customer Order Decoupling Point

   o: Olhager (2003)

   cite: Olhager, J. “Strategic positioning of the order penetration point.” IJPE 85(3), 2003.

   sum: Where you commit to specific demand defines your operating model. MTS, MTO,
   ATO, ETO are decoupling-point choices.

Day 4 — PARETO / ABC (lecture)

   f: ABC Analysis · 80/20

   o: Pareto (1896); Silver, Pyke & Peterson

   cite: Silver, E. A., Pyke, D. F. & Peterson, R. “Inventory Management.” Wiley, 1998.

   sum: Not every SKU deserves equal attention. ABC concentrates analytical effort where
   the dollars actually live.

Day 5 — EFFICIENT FRONTIER (lecture)

   f: Service-Cost Trade-off

   o: Fisher (HBR 1997)

   cite: Fisher, M. L. “What Is the Right Supply Chain for Your Product?” HBR, Mar–Apr
   1997.

   sum: Functional vs innovative products require different chains. The frontier separates
   the lazy from the optimal.

WEEK 2 · DEMAND

Day 6 — FORECAST ERROR · MAD/RMSE/MAPE (lecture)
  f: Forecast Accuracy Metrics

  o: Hyndman & Koehler (2006)

  cite: Hyndman, R. J. & Koehler, A. B. “Another look at measures of forecast accuracy.”

Day 7 — THE BULLWHIP EFFECT

  f: Bullwhip · 4 Causes

  o: Lee, Padmanabhan & Whang (1997)

  cite: Lee, H. L., Padmanabhan, V. & Whang, S. “Information Distortion in a Supply Chain:
  The Bullwhip Effect.” Mgmt Sci 43(4), 1997.

  sum: Demand variance amplifies upstream. Four causes: signal-processing, rationing,
  batching, price fluctuation.

  Case: Why Q3 Looks Worse Upstream

     pre: A 3% real demand uptick produced an 18% raw-material order at Tier-2. Your
     packaging supplier asks why.

     setup lines:

          // observed:

          // POS uptick +03%

          // operator orders +07%

          // DC orders to supplier +12%

          // tier-1 to tier-2 +18%

         blank

          // classic bullwhip signature. [amber]

          // supplier wants explanation.

     ctx: POS REAL=+3% · TIER-2=+18% · AMP=6× · CAUSE=TBD

     D1 “WHAT IS DRIVING THIS.”:

         good +2 → next:1 “SIGNAL PROCESSING / FORECAST RECALIBRATION” →
          “each tier interpreted the previous order as new demand info. lee’s first cause.
          correct diagnosis.”

          warn 0 → next:1 “OPERATORS HOARDING / RATIONING” → “plausible but
          premature. no shortage signal. you may be misdiagnosing forecast amplification
          as hoarding.”

          warn −1 → next:1 “BATCHED ORDERING / EOM” → “doesn’t fit the staircase
          amplification pattern. batching is lumpy, not progressive.”

      D2 “COUNTER-MOVE.”:

          good +2 “SHARE POS DATA UPSTREAM / EVERY TIER” → “classic dampener.
          when each tier sees real demand, they stop forecasting on noisy proxy. lee’s
          prescribed remedy.”

          warn 0 “CONSOLIDATE ORDERS / WEEKLY CADENCE” → “helps batching but
          not signal-processing. remedy for a different disease.”

          bad −2 “HOLD MORE SAFETY STOCK AT EACH TIER” → “lazy answer. absorbed
          variance with capital instead of attacking cause. cost compounds, problem
          persists.”

      optimal: [0, 0]

      fr: BULLWHIP IS AN INFORMATION FAILURE, NOT AN INVENTORY ONE. LEE,
      PADMANABHAN & WHANG (1997) IDENTIFIED FOUR CAUSES — EACH WITH A
      SPECIFIC COUNTER. THE PRINCIPAL DIAGNOSES THE CAUSE BEFORE
      PRESCRIBING. SHARING POS UPSTREAM IS THE HIGHEST-LEVERAGE
      INTERVENTION; IT ATTACKS THE PRIMARY CAUSE.

WEEK 3 · INVENTORY

Day 11 — EOQ · ECONOMIC ORDER QTY

   f: EOQ · Wilson Formula

   o: Harris (1913); Wilson (1934)

   cite: Harris, F. W. “How Many Parts to Make at Once.” Factory: The Magazine of
   Management 10(2), 1913.

   sum: The classic. Q* = √(2DS/H). The point isn’t the answer — it’s that the cost curve is
   flat near optimum.

   Case: The Reorder-Quantity Question

      pre: Reviewing reorder policy for shell-egg cases. Team orders weekly. CFO asks: “is
      this optimal?”

      setup lines:

           // inputs:

           // D (annual demand) 480,000 cases

           // S (cost per order) $480

           // H (holding cost) $1.20 / case / yr

           blank
    // current: weekly · Q ≈ 9,230 · 52 orders

    blank

    // CFO wants the math.

ctx: D=480k cases · S=$480 · H=$1.20 · CURRENT Q=9,230

quant:

    formula: Q* = √(2 D S / H)

    vars: [D, annual demand, 480,000] · [S, order cost, $480] · [H, holding cost,
    $1.20]

    result: Q* = √(2·480000·480/1.20) ≈ 19,596 cases · ~24.5 orders/yr

D1 “WHAT Q DO YOU RECOMMEND.”:

    bad −2 → next:1 “STAY WEEKLY · 9,230” → “you stayed 53% under optimum.
    annual cost gap ≈ $7,400 per category. defensible only if there is an unstated
    constraint.”

  f: Critical Fractile · Cu/(Cu+Co)

Day 41 — POWER OF RESILIENCE

   f: Sheffi · Resilience Quadrants

   o: Sheffi (2015)

   cite: Sheffi, Y. “The Power of Resilience.” MIT Press, 2015.

   sum: High-impact / low-probability disruptions need pre-built response capability.
   Sheffi: redundancy (slow, expensive) vs flexibility (fast, cheap).

   Case: The Single-DC Question

      pre: 94% of western US distribution flows through one DC in Reno. Disruption
      probability ~1.5%/yr. Recovery: 6–10 weeks.

      setup:

           // node analysis (Reno DC):

           // western US flow 94%

           // p(disrupt) annual ~1.5%

           // recovery time 6–10 wk

           // est. impact ~$48M

          blank

           // expected disruption: ~$0.7M/yr

          blank

           // VP asks: do we need a second site? [amber]

      ctx: FLOW=94% · P(DISRUPT)=1.5% · RECOVERY=6–10 wk · EXP $=$0.7M
       D1 “RESILIENCE INVESTMENT.”:

           warn −1 → next:1 “BUILD REDUNDANT DC ($14M CAPEX)” → “sheffi flags this
           — redundancy is expensive. payback at $0.7M/yr is 20 years. capex committed
           to a low-probability event with cheaper alternatives.”

           good +2 → next:1 “PRE-NEGOTIATED CO-PACK + 3PL FLEX CAPACITY” →
           “sheffi’s preferred move: flexibility, not redundancy. ~$0.4M/yr cost. payback in
           <2 years on expected disruption value, plus optionality.”

           bad −2 “ACCEPT EXPOSURE / MONITOR” → “$0.7M/yr unmanaged tail on a
           $48M event. betting against a known distribution. when it happens (over a
           decade, it will), you are the executive on the call.”

       D2 “WHAT YOU TELL VP.”:

           good +2 “EXPECTED-COST LANGUAGE / NPV CASE” → “VP understands. capex
           committee approves the flex contract. resilience becomes a defensible line item,
           not a panic spend.”

           warn 0 “RISK NARRATIVE / ‘RECENT EVENTS’” → “works for one cycle. when
           this VP rotates and the next one asks ‘why are we still paying for this,’ you have
           no defense beyond fear.”

       optimal: [1, 0]

       fr: SHEFFI (2015) DISTINGUISHED REDUNDANCY (BUILD TWO OF EVERYTHING)
       FROM FLEXIBILITY (BUILD ONE THAT CAN ADAPT, AND CONTRACT FOR THE
       REST). REDUNDANCY IS A CAPEX PROBLEM; FLEXIBILITY IS A CONTRACT-DESIGN
       PROBLEM. THE PRINCIPAL CHOOSES FLEXIBILITY WHEN THE ECONOMICS PERMIT
       — BECAUSE FLEXIBILITY ALSO CREATES OPTIONALITY THE BUSINESS NEVER
       ASKED FOR.

Day 47 — DECISION TREES & EVPI

   f: Expected Value of Perfect Info

   o: Raiffa (1968)
cite: Raiffa, H. “Decision Analysis.” Addison-Wesley, 1968.

sum: EVPI is the maximum you should pay for any information improvement. If a study
costs $X but EVPI < $X, the study is uneconomical regardless of quality.

Case: The Market-Study Question

   pre: A consultancy offers a $180k study that would resolve uncertainty on a $4M
   new-product procurement decision. Your team is split.

   setup:

        // the decision tree:

        // without study:

        // E[outcome] = $4M·(60%·1.2) +

        // $4M·(40%·0.6) = $3.84M

        // with perfect info:

        // always pick best = $4.32M

        // EVPI = $4.32M − $3.84M = $480k [amber]

       blank

        // study cost: $180k

        // study quality: ~70%

   ctx: STUDY $=$180k · EVPI=$480k · QUALITY=70% · EVII=$336k

   quant:

       formula: EVPI = E[max] − E[base]; EVII ≈ EVPI · quality

       vars: [EVPI, max value of info, $480k] · [q, imperfect info factor, 0.70] · [EVII,
       expected value imperfect info, $336k]

       result: EVII − Cost = $336k − $180k = $156k > 0 → BUY

   D1 “BUY THE STUDY OR NOT.”:

       good +2 “BUY · EVII > COST” → “correct. raiffa: EVPI gives the ceiling, study
       quality scales it down to EVII. $336k − $180k = $156k positive. you bought
       defensibly.”

       bad −2 “DON’T BUY · GUT FEELS EXPENSIVE” → “ignored a $156k expected
           gain because the headline looked big. classic anchoring failure raiffa warned
           about.”

           warn 0 “NEGOTIATE STUDY DOWN TO $100k” → “fine, but missed the lesson.
           the question was never the price — it was whether EVII justified the price. $180k
           with $336k EVII was already a buy.”

       optimal: [0]

       fr: EVPI IS THE SHARPEST TOOL IN DECISION ANALYSIS. IT GIVES YOU AN UPPER
       BOUND ON WHAT INFORMATION CAN BE WORTH — INDEPENDENT OF THE COST.
       RAIFFA (1968) FORMALIZED IT IN A WAY STILL OPERATIONALLY USED FIVE
       DECADES LATER. THE PRINCIPAL COMPUTES EVPI BEFORE EVALUATING ANY
       STUDY, RFI, OR ADVISORY ENGAGEMENT.

Day 53 — THEORY OF CONSTRAINTS

   f: TOC · The Goal

   o: Goldratt (1984)

   cite: Goldratt, E. M. & Cox, J. “The Goal.” North River Press, 1984.

   sum: Throughput is set by the slowest constraint. Improvements anywhere else are
   illusions. Five focusing steps: identify, exploit, subordinate, elevate, repeat.

   Case: Where Is the Bottleneck

      pre: A new product launch is missing volume targets by 12%. Six functions blame
      each other. You have one quarter.

      setup:

           // observed throughput gap: −12% [amber]

          blank

           // candidate constraints (utilization):

           // raw mat. supply 72% util

           // primary line 96% util [amber]
          // QA / inspection 81% util

          // secondary packaging 89% util

          // DC outbound 76% util

          blank

          // where do you focus.

      ctx: GAP=−12% · LINE=96% util · NEXT=89% · WINDOW=1 qtr

      D1 “IDENTIFY THE CONSTRAINT.”:

          good +2 → next:1 “PRIMARY LINE @ 96% UTIL” → “correct. goldratt step 1:
          identify. utilization near ceiling = the constraint. every other improvement is futile
          until this moves.”

          bad −2 “RAW MATERIAL @ 72%” → “low utilization is the consequence of a
          downstream constraint, not a constraint itself. you misread the system.”

          warn −1 → next:1 “QA / INSPECTION @ 81%” → “plausible candidate, but 96%
          beats 81%. work the highest first.”

      D2 “NEXT MOVE.”:

          good +2 “EXPLOIT THE LINE / OEE PROGRAM / SHIFT BALANCING” → “goldratt
          step 2: exploit before elevating. squeeze every minute out of the existing line
          before capex. typical lift: 8–14%.”

          bad −2 “BUY ANOTHER LINE ($8M CAPEX)” → “skipped step 2. elevation before
          exploitation is wasted capital. new line runs at 80% util and the question reopens
          in 18 months.”

          warn 0 “SUBORDINATE EVERYTHING ELSE TO THE LINE” → “goldratt step 3,
          executed before step 2. you would coordinate around the constraint without first
          making it as productive as it can be.”

      optimal: [0, 0]

      fr: GOLDRATT (1984) GAVE OPERATIONS THE FIVE FOCUSING STEPS. IDENTIFY,
      EXPLOIT, SUBORDINATE, ELEVATE, REPEAT. THE STEPS ARE ORDERED FOR A
      REASON: EXPLOITING IS NEAR-FREE; ELEVATING REQUIRES CAPEX. SKIPPING TO
      ELEVATION IS THE MOST EXPENSIVE COMMON ERROR IN MANUFACTURING.

8.2 Schema

 type State = {
      version: 2;
      streak: number;                                 // current consecutive-day streak
      currentDay: number;                             // 1..60
      lastCompletedDate: string | null;               // ISO date 'YYYY-MM-DD'

 type Completion = {
      dayNum: number;
      scenarioId: string;           // day title (e.g. "EOQ · ECONOMIC ORDER QTY")
      date: string;                 // ISO date
      picks: number[];              // option indices, in order
      score: number;                // sum of option scores
      accuracy: number;             // 0..100, % of optimal picks
      verdicts: ('good'|'warn'|'bad'|'lecture')[];
      isLecture: boolean;
 };



8.3 Migration
If loadState() finds a v1 schema (from 'scfc-machine-v1' ), do not migrate. The v2
program is a different curriculum. Initialize fresh state. (Optional: read v1 and warn the user
that progress can be reset; not required.)
8.4 Load / Save / Reset

 function loadState() {
     try {
          const raw = localStorage.getItem('scfc-masters-v2');
          if (!raw) return defaultState();
          return Object.assign(defaultState(), JSON.parse(raw));
     } catch (e) { return defaultState(); }
 }
 function saveState() {
     try { localStorage.setItem('scfc-masters-v2', JSON.stringify(state)); }
     catch (e) { /* swallow quota errors silently */ }
 }
 function resetState() {
     state = defaultState();
     saveState();
 }
 function defaultState() {
     return {
          version: 2,
          streak: 0,
          currentDay: 1,
          lastCompletedDate: null,
          completions: [],
          domains: Object.fromEntries(DOMAINS.map(d => [d.n, { strength: 0 }]))
     };
 }



8.5 Streak rules

 on completion (case OR lecture):
     today = today's ISO date
     if state.lastCompletedDate === today:       // already counted today → no change
          skip
     else if state.lastCompletedDate is yesterday:
          streak += 1
     else if state.lastCompletedDate is null:
          streak = 1
     else:                                        // gap of 2+ days
          streak = 1
     lastCompletedDate = today



8.6 Domain strength rules
 on completion:
    if isLecture:
        strength += 0.5   (cap at 5)
    else (case):
        if accuracy >= 80: strength += 1 (cap at 5)
        else if accuracy < 40: strength -= 1 (floor at 0)
        else: no change



8.7 Day advance

 on completion (case):
    if state.currentDay === activeDay.d AND state.currentDay < 60:
        state.currentDay += 1
 on completion (lecture):
    if state.currentDay === activeDay.d AND state.currentDay < 60:
        state.currentDay += 1


This ensures replays from the curriculum grid (loading a past day) don’t accidentally
advance the program.


8.8 Completions cap
Keep most-recent 80 completions. Older ones drop off. (Streak and domain strengths are
aggregated separately; losing old completions doesn’t affect them.)

9.1 Typewriter

 let _typingTimer = null;
 let _typingSkip = false;


 function appendLine(text, cls = '', cb) {
    const line = document.createElement('span');
    line.className = 'lcd-line ' + cls;
    lcdBody.appendChild(line);


    if (!text || text.trim() === '') {
        if (cb) setTimeout(cb, 40);
        return;
    }
     let i = 0;
     const cursor = document.createElement('span');
     cursor.className = 'cursor';
     line.appendChild(cursor);


     function step() {
         if (_typingSkip) {
             cursor.remove();
             line.textContent = text;
             if (cb) cb();
             return;
         }
         if (i < text.length) {
             cursor.before(document.createTextNode(text[i]));
             i++;
             _typingTimer = setTimeout(step, 10 + Math.random() * 8);
         } else {
             cursor.remove();
             if (cb) cb();
         }
     }
     step();
 }


 function clearLCD() {
     lcdBody.innerHTML = '';
     if (_typingTimer) { clearTimeout(_typingTimer); _typingTimer = null; }
     _typingSkip = false;
 }

11 · File structure

11.1 Single-file build (recommended for v1)

 /dist/
    index.html             (everything inline)


Inline order inside <head> : meta, title, font preconnect+stylesheet, <style> . Inline order

 /dist/
    index.html

    data.js       (DOMAINS, CURRICULUM, GLOSSARY, READING, exported as window.SCFC_DATA)

 <link rel="stylesheet" href="app.css">

12 · Acceptance criteria
The build passes when every item below is observably true.


12.1 Visual fidelity
   Panel renders with putty/aluminum gradient background.

   Four corner screws visible with diagonal slots.

   Hairline ridge texture overlays the panel surface (visible at close zoom).

   Nameplate shows SCFC—II / Masters Program · 60-Day Curriculum .

   Mode row has 5 buttons: Today / Curr / Gloss / Read / Cmd.

   LCD has visible scan lines (every ~3px).
   LCD has subtle flicker animation that does not distract.

   Cursor blinks while typewriter is active; disappears when line completes.

   Primary button has 6px mechanical depth at rest; compresses to 2px on press.

   Three primary-button color variants (red/amber/green) all render correctly.

   Streak block shows a 10-dot trend strip; dots are green for completed days.

   VU meters show 12 rows, one per domain, with 5-cell bars.


12.2 Curriculum
   Day 1 loads on first run.

   All 60 days are reachable from the curriculum grid.

   Curriculum grid groups days by week with the domain label visible.

   At least 12 days are full case scenarios (1, 7, 11, 12, 16, 19, 20, 21, 28, 36, 39, 41, 47, 53).

   All 48+ lecture days render the framework card and the “Mark Lecture Complete”
   button.


12.3 Case scenario flow
   Engaging a case types out the brief letter-by-letter.

   Clicking the LCD mid-typing fast-forwards remaining lines.

   The context table renders below the brief.

   Quantitative panels render for cases that have one (Day 11, 12, 47).

   Continue advances to the first decision.

   Channel buttons arm (amber LED pulse) when a decision is presented.

   Pressing a channel button dims the others and shows the verdict.

   VU meter for the current domain flashes gold cells in sequence on outcome.

   Options with a .n field route to that decision; otherwise route to debrief.

   Debrief shows path taken, total score, accuracy, principal framing, framework card.

   Eject returns to home and currentDay advances by 1 (unless at day 60).


12.4 Lecture flow
   Lecture days show framework card on the home view.

   “Mark Lecture Complete” button is visible.

   Pressing it advances currentDay and increments domain strength by 0.5.


12.5 Persistence
   Completing a day persists state in localStorage under key scfc-masters-v2 .

   Reloading the page returns to the same currentDay .

   Streak increments correctly on consecutive-day completion.

   Streak resets to 1 when a day is skipped.

   Domain strengths persist and update per §8.6.

   Reset palette command clears state and returns to Day 1 with streak 0.

   Loading a previously-completed day from the curriculum grid shows the prior debrief
   (no double-counting).

   Replay does not modify streak, completions, or domain strengths.

13 · Out of scope
The following are explicitly not part of this build:

    Multi-user support, accounts, login, sync.

    Server-side anything.

    Adaptive AI coaching (use generated content). All scenarios are authored.

    Spaced repetition / forgetting curve scheduling.

    Audio, sound effects.

    Animated illustrations beyond the LCD typewriter, VU flash, and button states.

    A “tutorial” or onboarding flow. The interface is the tutorial.

    A “share my progress” button.
   Print-to-PDF / export of the curriculum.

   Gamification beyond streak and domain strength (no badges, levels, unlocks).

   A “settings” panel. There are no settings.

If the user requests any of the above, defer to a v3 spec. Do not bolt them on.

16 · Definition of done
The build is done when:
